# MV-DL2125 — сканирование неподвижной детали (MVS SDK, Python)

Скрипт для лазерной 3D-камеры **Hikrobot MV-DL2125-04H-R** (GigE). Снимает одну деталь
по программному триггеру, сохраняет облако точек, считает высоту/объём и отдаёт результат
наружу по Modbus TCP (ПЛК) или TCP+JSON (SCADA).

Внешних зависимостей нет. numpy нужен только для `--measure` (расчёты), сама съёмка и
сохранение файлов работают без него.

## Статус

| Задача | Состояние |
|---|---|
| Съёмка кадра (Mono8, снимок лазерной полосы) | работает |
| PNG/BMP/JPG/TIF, RAW + JSON | работает |
| Переключение `--image-mode PointCloud3D` | проверено на камере: принимается, `PixelFormat` становится `Coord3D_C16` (`0x011000B8`), payload 10852 байт |
| Приём 3D-кадра | кадр пока не приходит (`0x80000007`), в том числе в free-run — триггер ни при чём, камера в 3D-режиме не шлёт данные по видеопотоку. Проверяются гипотезы: переоткрытие камеры (`run.cmd 12`), chunk-данные (`run.cmd 13`), приём в MVS GUI |
| Chunk-данные (толщина и т.п.) `--chunk` | добавлено, нужно проверить на камере |
| Облако точек PLY/CSV/OBJ | код готов, нужен 3D-кадр (`Coord3D_*`), сейчас падает с `0x80000500` |
| Замеры (высота, объём) | код готов, нужен 3D-кадр |
| Выдача в ПЛК Modbus TCP / TCP+JSON | код готов |

## Требования

* Windows с установленным **MVS SDK v4.8.x** (проверено на 0x04080202, прошивка V2.4.0 250613)
* Python 3.8+ (проверено на 3.11), скрипт запускается из каталога с примерами SDK либо сам
  находит `MvImport` через переменную окружения `MVCAM_COMMON_RUNENV`
* камера в той же подсети, например: IP `192.168.51.182`, серийник `02DB1432164`

## Быстрый старт

```bat
python dl2125_scan.py --list                              :: камеры видны?
python dl2125_scan.py --count 1 --ply --png --measure     :: первый скан
```

либо через `run.cmd` (см. ниже): `run.cmd 1` → `run.cmd 3`.

## Ключевая особенность: Mono8 ≠ карта высот

Камера по умолчанию отдаёт кадр `Mono8` — это **снимок лазерной полосы**, а не 3D-данные,
поэтому `MV_CC_SavePointCloudData` возвращает ошибку `0x80000500`.

В дампе параметров найден узел **`ImageMode`** со значениями:

| Значение | Что отдаёт камера |
|---|---|
| `Origin` | 2D-изображение (Mono8) — текущий режим по умолчанию |
| `PointCloud3D` | кадр 3D-данных (`Coord3D_*`) — из него строится облако точек |
| `Range3D` | карта высот |
| `PkgMask` | маска упакованного объекта (логистика DWS) |

Переключение: `--image-mode PointCloud3D`. После переключения в отчёте печатается новый
`PixelFormat` и `PayloadSize` — если формат стал `Coord3D_*`, PLY/замеры заработают.

Также у камеры есть **chunk-данные** (прикладываются к кадру): селекторы `Image`,
`Thickness` (толщина), `RunDir` — включаются ключом `--chunk` и печатаются в консоли с
числовой расшифровкой. Событие `DwsVolume` («объём посчитан») включается `--event DwsVolume`,
но payload события прошивкой не заполняется — по нему виден только факт готовности.

## Командная строка (основные ключи)

| Ключ | Назначение |
|---|---|
| `--list` | перечислить камеры и выйти |
| `--serial SN` / `--index N` | выбрать камеру |
| `--count N --interval S` | сколько сканов и с какой паузой |
| `--timeout MS` | таймаут ожидания кадра (по умолчанию 5000) |
| `--free-run` | непрерывный поток кадров вместо программного триггера |
| `--exposure US --gain G` | экспозиция и усиление |
| `--image-mode MODE` | `Origin` / `PointCloud3D` / `Range3D` / `PkgMask` |
| `--chunk SEL` | включить chunk-данные (можно несколько раз) |
| `--event NAME` | включить событие камеры (`DwsVolume`) |
| `--ply --csv --obj` | сохранить облако точек (по умолчанию, если формат 3D) |
| `--png --raw` | сохранить изображение / сырые байты + JSON с метаданными |
| `--measure` | посчитать высоту и объём (нужен numpy и 3D-кадр) |
| `--z-scale N` | единиц SDK на 1 мм по Z (1000 = микрометры; по умолчанию 1000) |
| `--x-mm-per-px X --y-mm-per-px Y` | размер пикселя в мм (по умолчанию 0.1) |
| `--base-mm V` | уровень опорной плоскости в мм (по умолчанию — минимум валидных точек) |
| `--out DIR` | каталог результатов (по умолчанию `./out`) |
| `--params-save F` / `--params-load F` | сохранить/загрузить все параметры камеры |
| `--dump-params [F]` | выгрузить дерево параметров и выйти (`--dump-all` — все узлы) |
| `--modbus-host H` + `--modbus-port/unit/addr` | отправка в ПЛК по Modbus TCP |
| `--json-host H` + `--json-port` | отправка одной JSON-строкой по TCP |

## Выдача в ПЛК / SCADA

**Modbus TCP** (функция 0x10 Write Multiple Registers, IEEE754, старший регистр первым,
по 2 регистра на float):

| Адрес (смещение от `--modbus-addr`) | Значение |
|---|---|
| +0, +1 | высота, мм (`height_mm`) |
| +2, +3 | объём, см³ (`volume_cm3`) |
| +4, +5 | число валидных точек (`valid_points`) |
| +6, +7 | доля заливки поля 0..1 (`fill_ratio`) |

**TCP+JSON** — та же структура результата одной строкой UTF-8 с `\n` на конце (нужен свой
приёмник или совместимый вход SCADA).

## Замеры

`--measure` разбирает кадр `Coord3D_*`, отбрасывает NaN/невалидные точки, базовая
плоскость — минимум Z (или `--base-mm`). Высота = `z_max - z_base`, объём = сумма
`(z - z_base)` по точкам × площадь пикселя. Масштаб задаётся `--z-scale` и
`--x-mm-per-px` / `--y-mm-per-px` — их нужно подогнать по фактической калибровке.

## Ограничения и известные проблемы

* SDK принимает только ASCII-пути: не-ASCII символы в путях к файлам автоматически
  заменяются транслитерацией (функции `sdk_path`, `safe_out_dir`).
* Отдельного примера под облако точек в SDK нет; ключевая функция —
  `MV_CC_SavePointCloudData` (`MvImport/MvCameraControl_class.py`).
* TCP-выход объёма самой камеры (`VolumeOutputEnable`, `TCPClientEnable`) взаимоисключен
  с доступом по SDK (согласно FAQ производителя) — в скрипте не используется.
* Полезная нагрузка событий (`pEventData`) прошивкой не заполняется.
* Выходные коды: `0` — успех, `1` — камера не найдена, `2` — ошибка.

## run.cmd

`run.cmd` (в этой же папке) собирает команды, которые нужны для проверки; запуск: `run.cmd N`

| N | Команда |
|---|---|
| 0 | синтаксическая проверка `python -m py_compile` |
| 1 | перечисление камер (`--list`) |
| 2 | полный дамп параметров камеры (`--dump-params --dump-all`) |
| 3 | **основной тест**: скан в режиме `PointCloud3D` + PLY + PNG + RAW + замеры |
| 4 | тест режима `Range3D` |
| 5 | тест chunk-данных `Thickness` + `Image` |
| 6 | рабочий прогон: замеры + отправка в ПЛК/SCADA (если заданы `MODBUS_HOST` / `JSON_HOST`) |
| 7 | сохранение текущих параметров камеры в файл |
| 8 | 3D-скан: один триггер, таймаут 30 с (проверка «долгой» сборки) |
| 9 | 3D-скан в free-run без триггера (идут ли кадры вообще) |
| 10 | 3D-скан: 201 программный триггер, затем ожидание 30 с (сборка из линий) |
| 11 | 3D-скан: серия из 100 кадров на один триггер (`--burst 100`) |
| 12 | 3D-скан: переоткрытие камеры после смены режима (`--reopen`, перерегистрация видеопотока) |
| 13 | 3D-скан с включёнными chunk-данными `Image` + `Thickness` |

Если Python недоступен как `python`, задайте свой путь: `set PY=C:\path\to\python.exe`
перед запуском. Серийник камеры задаётся переменной `SN` (по умолчанию `02DB1432164`).
